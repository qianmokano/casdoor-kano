# Casdoor 后续发布版本命名

用户要求与 sub2api 同步，从下次发布起使用 `v<上游版本>-<序号>`。当前 fork 基线为上游 `4.13.0`，下一个未使用的新格式标签为 `v4.13.0-1`；同一上游版本按 `-2`、`-3` 递增，升级上游后重置为 `-1`。历史 `v4.13.0-kano.N` 标签、镜像和发布记录保留原名。

Kano portal 工作流不再硬编码 `4.13.0-kano.*`；改为数字后缀触发，先校验完整标签及 `kano/main` 来源，再执行现有 portal 回归和双架构固定 GHCR 镜像发布。配置回归在 PR、分支和手动运行时执行，并验证上游工作流仍仅能在官方仓库发布。

构建原有 `GetVersionInfo` 将完整 Git 标签写入二进制，页面直接显示该版本，没有重复添加 `v`。本次不更改账户、认证、版本生成或业务代码。

本次只准备下次发布所需规则和源码，不创建标签、不更新 VPS 或生产配置。标签与工作流回归及原 Build、Kano portal 检查通过后合并到 `kano/main`，结果另记发布记录。

本地验证：五组标签与工作流回归和 Bash 语法通过，差异检查无空白错误。远端未存在 `v4.13.0-<数字>` 标签。原业务代码未变，全部现有 Go、前端、API 和浏览器回归仍由原 CI 执行。
