# 公开首页加载优化

线上 `v4.13.0-kano.1` 的移动端 Lighthouse 性能分为 74；FCP 2.6 秒、LCP 4.2 秒、Speed Index 9.3 秒。页面截图证实加载期间先空白、后显示会话查询等待状态，最后才显示首页。

依据：`HomePage` 等待 `/api/get-account` 后才加载首页独立模块，中文资源也在首页挂载后才切换。公开首页还请求远端 Casdoor 图标。这些请求在真实外网增加串行等待。

改动：首页随主模块加载，立即展示公开内容，会话返回后仍按原权限跳转；控制台框架只在其路由需要时加载；中文与英文资源随主模块加载，根路径在无语言偏好时默认中文；服务端仅为根路径的首页 HTML 设置本地图标和响应式图片预加载，其他认证与控制台路由保留组织品牌。

验证：新增静态资源测试、类型检查、静态检查与构建通过；Cypress 21 项通过，包括慢会话首屏与已登录客户跳转。首次优化后本地生产构建移动端性能 91，FCP 2.6 秒、LCP 2.8 秒、Speed Index 2.6 秒、CLS 0；根据未使用脚本诊断继续按需加载控制台框架，减轻公开页面的脚本负担。CI 和上线后性能复测继续验证。

生产业务数据仅进行读取。API 网关的用户表汇总在在线计费过程中可能变化，必须核对变动与用量记录，不能以汇总不一致直接推断身份迁移损坏，也不能宣称所有余额完全不变。

只读检查：基线后网关产生 25 笔付费用量，来自一个用户，合计 0.2113092；用户数保持 130，API Key、身份关联与订阅的摘要相同。商店 16 笔订单、身份关联、钱包摘要相同。已验证商店页内登录与两站 OIDC 回调，并为后续版本保存了独立的稳定用户字段摘要；没有替换原始基线。完整用户表摘要含余额，不能追溯到具体变化字段，因此仅把计费活动作为余额变化的合理依据。
