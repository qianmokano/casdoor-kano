# Casdoor Kano fork 部署与恢复

生产目录为 `/opt/casdoor`，主机 Nginx 为 `auth.kanoapi.top` 提供 HTTPS；应用只绑定 `127.0.0.1:8000`。保留当前 Nginx 与 Certbot 配置，VPS 不编译源码。

## 发布前

1. 从 `kano/main` 新建功能分支，逐项检查现有改动归属。只暂存本次文件。
2. 运行相关 Go 测试、覆盖率、前端类型检查、lint、构建、独立实例的真实 API 测试及 Cypress。
3. 推送并创建 PR。原 `Build` 与 `Kano portal` 全部通过后合并到 `kano/main`。
4. 在已合并且通过检查的提交上创建未使用过的 `vX.Y.Z-N` 标签；`X.Y.Z` 对应上游版本，`N` 是从 1 开始的 fork 发布序号。下次发布使用 `v4.13.0-1`，同一上游版本后续为 `v4.13.0-2`、`v4.13.0-3`，升级上游后从新版本的 `-1` 开始。工作流先校验标签和 `kano/main` 来源，再运行验证并发布两个架构的固定镜像；验证 VPS 拉取成功后再停服务。

镜像不可覆盖旧标签；升级上游版本需重新评估数据迁移。生产配置、身份库、应用凭据、签名密钥、上传资源和会话不提交到 Git。

新规则从下一次发布起生效。历史 `v4.13.0-kano.N` 标签、镜像和发布记录保留原名，不移动或重用。新镜像格式为 `ghcr.io/qianmokano/casdoor-kano:v4.13.0-1`，实际应用版本由构建时的 Git 标签生成。

## 持久化与账户配置

保留现有 Compose 参数及 `conf`、`data`、`logs` 挂载。在首次切到 fork 时增加：

```yaml
volumes:
  - ./conf:/conf
  - ./data:/data
  - ./logs:/logs
  - ./files:/files
  - ./tmp:/tmp
```

从旧容器复制现有 `/files` 和文件会话 `/tmp`，再切换容器，不能用空目录遮住旧文件。新目录确保容器 UID 1000 可写。只增加这些已核对的挂载，不用示例覆盖完整生产 Compose。

头像需要 `Storage / Local File System` 提供方，域名为 `https://auth.kanoapi.top`。将其关联到两个 `kano` 应用，保留原邮件、验证码和认证提供方。按实际 `signupApplication` 或组织默认应用核对导入用户也能上传。用户资源通过原头像路径及权限校验保存到 `/files/avatar/kano/`。

将 `kano` 组织 Email 项设为 `viewRule=Self`、`modifyRule=Admin`，其余规则保持原样。普通账户的更新与邮箱重置接口另有后端拦截；配置和页面隐藏不替代该拦截。不新增或替换应用 Client ID、Secret、证书和用户 UUID。

## 停写备份与恢复验证

1. 记录当前镜像、镜像 ID、容器、挂载及应用版本；先拉取新镜像。旧镜像保留在本机，并创建明确的回退引用。
2. 停止 Casdoor，让 SQLite 和文件会话停止写入。备份 Compose、环境文件（若存在）、完整 `conf`、完整 `data`、持久资源和会话目录。运行中的 `.db` 单文件复制不算完整备份。
3. 从停止的旧容器复制尚未持久化的 `/files`、`/tmp`，与主机目录一起写入权限受限的备份目录；备份不得放到公开网站目录。
4. 计算备份所有普通文件的 SHA-256，打包后解压到独立目录，逐项验证散列；对恢复出的 SQLite 执行 `PRAGMA integrity_check`，核对用户和应用数量。
5. 用新镜像和恢复副本启动独立容器，仅绑定 `127.0.0.1:18801`。核对配置、静态页面和 OIDC discovery；停止测试容器，确认用户稳定标识、密码散列、应用接入凭据及签名材料仍与备份相同。该副本不用于向真实用户发邮件或修改真实凭据。
6. 验证通过后才修改实际 Compose 镜像和必要持久化配置，并应用上述邮箱及存储配置。执行 `docker compose up -d`，检查容器状态、日志、生产 discovery、首页、普通用户和管理员登录，以及两站页内登录与 OIDC 回调。

备份和恢复副本内含敏感运行数据，留在服务器受限目录。部署完成后按运维策略复制到 VPS 外，并定期演练恢复。

## 回退

若上线验收失败，停止新 Casdoor 容器，保存故障现场，再同时恢复旧镜像、Compose、配置、完整数据库、资源和会话目录，确认权限后重启。若版本启动修改了数据库结构，不能仅回退镜像。

通过原备份的文件散列和 SQLite 完整性检查后，检查 HTTPS、管理员入口、两个应用的登录及原业务身份映射。回退的业务数据以备份时刻为边界；停机后产生的身份修改不能默认为已迁回。
